# 排期表（schedule table）字段定义

排期表是整个工作流的**唯一数据源**：视频文件名、标题、话题、短标题、定时、合集、原创、状态全在一张 CSV 里。

## 字段

| 字段 | 必填 | 说明 | 示例 |
|------|------|------|------|
| 视频文件 | ✅ | `videos/` 里的文件名，必须**完全一致**（含扩展名） | `01_拒绝面试见光死_Kira面试通关秘籍.mp4` |
| 标题 | ✅ | 发布时的描述文字主体，建议 ≤ 30 字 | `准备 Kira 面试前，请先听我一句劝` |
| 话题 | ✅ | `#话题 #话题` 形式，4–6 个为宜 | `#Kira面试 #加拿大留学 #MockView` |
| 短标题 | 建议 | 视频号「短标题」字段，≤ 10 字最好 | `请先听我一句劝` |
| 定时发布时间 | 可选 | `YYYY-MM-DD HH:MM`。**脚本不自动填**，人工在草稿箱设 | `2026-10-22 19:00` |
| 合集 | 可选 | 脚本**通常填不进去**（输入框默认折叠），人工在草稿箱补 | `加拿大本科申请` |
| 原创声明 | 建议 | `是` / `否`，填 `是` 会自动勾选并点「同意」 | `是` |
| 状态 | ✅ | 见下方状态机 | `待上传` |

## 状态机

```
待上传 ──上传成功──► 待确认   （已存草稿，等人工改封面/定时后发表）
   │
   └──失败──► 失败
待确认 ──人工发表──► 已发布
```

`待上传`、`待发布`、`pending`、`todo`、空字符串，**都算待处理**，脚本都会捞出来跑。

## CSV 生成规范

- 编码：`utf-8-sig`（带 BOM），Excel 直接双击打开不乱码
- 换行：`newline=""`，避免 Windows 下空行
- 脚本每处理完一条就回写整张表 → **断点续跑**就靠这个

```python
import csv
header = ["视频文件","标题","话题","短标题","定时发布时间","合集","原创声明","状态"]
rows = [[...], [...]]
with open("视频号排期表_xxx.csv","w",encoding="utf-8-sig",newline="") as f:
    w = csv.writer(f); w.writerow(header); w.writerows(rows)
```

## 表头名容错

脚本用 `FIELD_MAP` 做表头映射，以下写法都能识别：

| 内部字段 | 可接受的表头 |
|---------|-------------|
| video | 视频文件 / video |
| title | 标题 / title |
| topic | 话题 / topic |
| short_title | 短标题 / short_title |
| publish_time | 定时发布时间 / publish_time |
| collection | 合集 / collection |
| original | 原创声明 / original |
| status | 状态 / status |

表头写错 → 该列读不到值 → 对应字段留空。排期表里 `视频文件` 和 `状态` **必须**能被识别，否则脚本跑不起来。

## 标题怎么写

视频号标题用「Mel Robbins 两行钩子」结构（场景锚点 + 大白话劝告）。改写方法、公式库、自检脚本见 skill **`mel-robbins-hooks`**：

```bash
python ~/.workbuddy/skills/mel-robbins-hooks/scripts/lint_copy.py --file 排期表.csv
```

标题写法会直接影响视频号打开率，值得每次改完都过一遍自检。

## 同一批内容的云端版本

排期表建议同时存一份到 WorkBuddy 资料库（数据表节点），本地 CSV 作为脚本执行源。改文案时两边同步：
- 本地 CSV → 脚本读它跑批
- 云端数据表 → 团队/多设备共享与查看
